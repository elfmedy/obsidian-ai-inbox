# AI Inbox 开发计划

版本：1.2 · 日期：2026-09-12 · 状态：P0 原型已实现，采用开源参考修订取数路线，实机联调进行中。

依据：`requirements-baseline.md`、`detailed-design.md`。验收编号见 `acceptance-tests.md`。

执行记录：见 `technical-spikes.md`。2026-09-12 已完成可加载的 P0 两端原型和 90 项自动测试；P0-02～P0-05 尚未全部验收，不能标记 P0 完成。发布规范提前纳入 `../PUBLISHING.md`，不改变 P0→P6 的功能开发顺序。

开源复用决策见 `open-source-review.md`：已基于 ThierryAbalea/chatgpt-conversation-export 接入当前接口分页，并据 Pionxzh exporter 修正工具图过滤风险。后续优先复用图片 resolver、引用转换和 Markdown 库；不再自行探索已有源码说明的格式。严格保存策略仍由本项目实现。真实长聊天和生成图尚未通过，不因上游支持而缩减验收。原工作量先保留，P0 收尾时依据复用效果重估。

## 1. 目标与执行方式

第一个可交付版本必须完成：**一键读取当前聊天全部消息 → 下载全部内容图片 → 写入 Obsidian → 重复保存按本地正文状态更新或另存**。

不把“只能抓屏幕里几条消息”“图片只有远程链接”或“只会新建文件”定义为完成版。可以用无图样本打通中间里程碑，但首版发布必须包含图片完整链路。

每次开发任务以任务 ID、输入、输出、验收和非目标为边界；完成后更新任务状态并记录测试证据。每个阶段只在新增变化或未解决风险需要时扩展测试，避免反复跑无关检查。

开发和故障注入全部使用独立测试 Vault，不使用日常知识库。实际发布到商店和社区属于最后的发布操作；本计划不等于现在开始发布。

## 2. 阶段顺序与工作量

按一个熟悉 TypeScript 的开发者、借助编码工具、能使用真实 ChatGPT 测试账号和 Obsidian 桌面环境估算。一个开发日按约 6 小时有效工程工作计，不是模型调用耗时。范围包括编码、联调、测试及文档，不包含商店审核等待。

| 阶段 | 目标 | 依赖 | 估算 |
| --- | --- | --- | --- |
| P0 | 验证完整抓取、图片获取、本机连接与编辑保护 | 已确认需求 | 3–5 开发日 |
| P1 | 工程骨架、Schema、测试样本与确定性渲染 | P0 取数路线可行 | 1–2 开发日 |
| P2 | Obsidian 保存核心、身份、另存和 properties 保护 | P1 | 4–6 开发日 |
| P3 | ChatGPT 抓取与完整图片链路 | P0、P1；集成依赖 P2 | 4–7 开发日 |
| P4 | 一个按钮的端到端体验和连接 | P2、P3 | 3–5 开发日 |
| P5 | 并发、崩溃恢复、资源与权限边界 | P4 | 3–5 开发日 |
| P6 | 自用试运行、打包和发布准备 | P5 | 2–3 开发日 |

基准合计 **20–33 开发日**。建议为网页适配和图片权限问题预留约 20%，总预算约 **24–40 开发日**。这是初始工作量估算，P0 完成后必须根据实际取数方式重估；不以压缩验收来满足日期。

依赖主线：`P0 → P1 → P2/P3 → P4 → P5 → P6`。单开发者默认按表顺序执行；P2/P3 逻辑上可独立推进，但本计划不要求多代理并行。

## 3. P0：先验证最难的四条链路

目标：用小型原型回答“完整聊天和原图能否可靠获取，以及本地编辑能否可靠保护”。此阶段允许原型代码，不能直接把验证脚本包装成正式版。

| ID | 任务与交付物 | 完成条件 |
| --- | --- | --- |
| P0-01 | 建立自建测试聊天、测试 Vault，记录 Chrome/Obsidian/Windows 实际版本 | 样本可重放，无私人聊天进入仓库 |
| P0-02 | 验证普通与长聊天、滚动区外消息、分支、生成中切换 | 短聊天与至少 200 条消息的长聊天无遗漏；有首尾/顺序证据；不能证明时可靠失败 |
| P0-03 | 验证上传图、生成图、多图、签名过期、外链图、blob 路线 | 实際图片字节下载并在断网 Vault 中显示；明确认证与权限路径 |
| P0-04 | 验证 MV3 → loopback 接收、权限和 worker 重启 | 不依赖常驻后台；绑定指定 Vault；测试端口占用与服务未启动 |
| P0-05 | 验证 Vault.process、打开编辑器、同时输入和 properties 改动 | 原型不能丢用户编辑；确定最终写入前检查方法 |
| P0-06 | 输出 `docs/technical-spikes.md`、开源审查与设计修订 | 写明主取数路线、上游版本/许可、失败样本、支持矩阵、风险和重估工作量 |

**阶段门槛**：P0-02～P0-05 全部通过。图片或完整抓取失败则继续修正适配路线；若只能通过增加权限/改变产品范围解决，提交具体证据和建议再请用户选择。

本阶段先不做：精美 UI、商店素材、多来源、批量导出、模板定制。

## 4. P1：建立开发骨架与公共契约

建议目录：

```text
apps/
  extension/
    src/{ui,background,adapters,assets}/
  obsidian-plugin/
    src/{transport,persistence,settings}/
packages/
  protocol/src/
  core/src/
tests/
  fixtures/{chatgpt,markdown,images}/
  integration/
  fault-injection/
docs/
```

| ID | 任务与交付物 | 验收 |
| --- | --- | --- |
| P1-01 | workspace、TypeScript strict、打包、lint、格式化、单元测试命令 | 两端最小产物可构建、加载；无业务功能也可干净卸载 |
| P1-02 | 完整 ContentBlock 联合、Snapshot、Request/Result/Error Schema | 运行时校验与 TS 类型一致；拒绝未知危险字段、路径注入、超大输入 |
| P1-03 | 规范化/hash 规范、黄金输入和 Markdown 渲染；优先评估 citations/Defuddle/mdast 复用 | A06～A09、H01～H04；相同输入输出字节稳定，未解析引用不静默删除 |
| P1-04 | 脱敏测试样本、真实页面适配版本标记 | HTML/结构化输入有来源说明、预期消息数量及图片清单 |

交付：可安装的空壳插件/扩展、公共协议模块、测试夹具和通过的构建。P1 不把测试数据抓取器误当正式抓取器。

## 5. P2：先做能证明安全的保存核心

这一阶段用固定快照直接驱动保存核心，不等待网页 UI，先把产品最重要的规则测实。

| ID | 任务与交付物 | 验收 |
| --- | --- | --- |
| P2-01 | VaultStore、PluginState、版本迁移入口和测试替身 | 加载/损坏索引有明确分支，不基于现存正文伪造未编辑基线 |
| P2-02 | 保存决策纯函数与真实 Vault 写入 | S01～S08，严格本地修改优先 |
| P2-03 | frontmatter 边界提取、原文保留与 malformed 防护 | S09～S11；用户属性、YAML 注释、顺序不丢 |
| P2-04 | noteId 映射、rename/move/delete/duplicate 处理 | F01～F06；不按标题猜目标 |
| P2-05 | 日期命名、同秒碰撞、Windows 名称/路径处理 | F07～F09；任何新建不得覆盖同名文件 |
| P2-06 | 最终写入前校验、editor buffer 检查和另存降级 | C01、C02；真实编辑器输入不被覆盖 |
| P2-07 | PendingCommit 最小持久化与写后索引 | X01～X04；为 P5 故障注入建立检查点 |

交付：可以在独立 Vault 重放完整保存矩阵的插件核心。阶段演示必须包含：首次保存、续聊更新、本地修改后来源不变仍另存、随后只更新新目标。

## 6. P3：正式抓取和图片本地化

| ID | 任务与交付物 | 验收 |
| --- | --- | --- |
| P3-01 | 基于 P0 实测路线实现 ChatGPT adapter | A01～A05、A10；当前完整聊天和稳定身份 |
| P3-02 | 代码、表格、公式、列表、链接转换 | A06～A09；内容保真，无 UI 噪声 |
| P3-03 | 参考 Pionxzh/OwlCt 建立图片清单、下载解析、来源权限、原图检查，覆盖工具消息生成图 | I01～I05、I12；图片在断网 Vault 可读 |
| P3-04 | IndexedDB 暂存、分块传输、摘要验证 | I06、I07、X05；大图不撑爆消息通道 |
| P3-05 | 本地资源去重、缺失恢复、用户图片修改保护 | I08～I11；不覆盖历史或用户资源 |
| P3-06 | 图片全完成后才提交的约束 | I05、I07；失败时目标笔记不变 |

交付：自建 ChatGPT 聊天的真实文本和图片经扩展落入 Vault，无需复制正文或手工下载图片。

不得降级：用截图替代所有图片、只导最新几轮、把损坏图片写进笔记、忽略下载失败并报成功。

## 9. P6：试运行和发布准备

1. 用自建聊天完整跑回归，并在获准的真实使用样本上试用；日志保持脱敏。
2. 在全新 Chrome 配置和测试 Vault 重新安装，验证连接、令牌重置、升级和停用清理。
3. 整理 README、安装指南、数据与权限说明、支持内容矩阵、已知限制、反馈模板。
4. 生成扩展 ZIP、Obsidian `main.js`/`manifest.json`/`styles.css`（如需要）和版本信息，校验包内容不含私有样本、凭据、暂存数据。
5. 准备 Chrome 商店与 Obsidian 社区提交材料；实际提交时再次核对当时的官方要求，不将审核耗时算入开发完成日期。

发布门槛：验收文档中全部阻断级用例通过；无已知数据丢失问题；所有失败会清楚反馈；支持矩阵与实现相符；已测版本明确；关键依赖与许可记录完整。

## 10. 风险与触发行动

| 风险 | 触发证据 | 行动 |
| --- | --- | --- |
| 页面只能提供部分历史 | P0 长聊天无法证明首尾与顺序 | 优先换取数路线；不继续做依赖截断快照的保存功能 |
| 图片需不同认证上下文 | 上传图/生成图下载失败或返回登录 HTML | 分离图片 resolver，实测权限，不把 Cookie 传给插件 |
| 网页内部接口变化 | 固定样本与真实页面结果不一致 | 适配器失败关闭、更新夹具和适配器版本 |
| Obsidian 编辑缓冲竞态 | 用户输入被覆盖或保存到旧版本 | 调整 Writer；无法证明安全的打开状态保守另存 |
| 多文件写入中断 | 笔记写入与索引结果不一致 | 基于 pending 前后摘要恢复；不盲目重放新建 |
| 文本与图片体量过大 | 内存或任务生命周期超预算 | 流式/分块、限制并发、明确超限，不截断 |
| UI 被异常选项挤满 | 正常保存需要选择范围或模式 | 把工程参数改为内部常量/一次设置，维持一个按钮 |
