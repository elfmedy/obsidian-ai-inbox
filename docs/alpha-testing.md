# AI Inbox 0.2.0 Alpha：安装与验收

更新：2026-09-12。此包已经具备完整保存链路，不再是只输出诊断 JSON 的 P0 探针。真实 ChatGPT 的长聊天、生成图和分支仍缺少验收样本，因此当前交付为 Alpha，不能标记全部发布门槛通过。

## 更新到 0.2.0

项目专用 `p0-vault` 已更新并重新启用 AI Inbox 0.2.0，原连接凭据保持不变。Chrome 扩展管理页中重新加载 AI Inbox，确认版本 0.2.0，并刷新聊天。在其他仓库使用时，两端都应更新；旧 Obsidian 插件不提供自动发现接口。原来已经配对的浏览器连接可以继续使用，首次连接新仓库时确认一次即可。

0.2.0 自动发现运行中且启用了 AI Inbox 的仓库。一个仓库时首次保存显示配对码，在 Obsidian 确认后继续保存；多个仓库且未设默认时打开仓库选择页。右键图标→「切换仓库 / 设置」可随时改选，成功连接后它立即成为默认。没有单独的“设为默认”开关。

未运行或默认仓库不可用时直接失败，不抓取新聊天、不新增离线待发送任务、不提供“打开 Obsidian 并继续”按钮，不自动改投其他仓库。已有提交中断的恢复记录仍保留，手动再次保存时先核对原回执；这是防重复提交机制，不是离线收集模式。

工具栏使用新的原创“对话气泡 + 收件托盘”圆角图标，提供 16/32/48/128 像素 PNG；各状态图标保持一致，没有徽标和默认 popup。设置页改为默认仓库卡片与可用仓库列表，不再显示连接 JSON 输入框。

新图片遵循 Obsidian“文件与链接 → 附件默认存放位置”：仓库根目录、指定文件夹、与笔记同目录、笔记目录下子文件夹。相对目录以最终保存/更新的笔记位置为准，不跟随当前活跃编辑器。已有笔记的有效图片引用不迁移，旧 `_assets` 内容不删除；另存和新增图片采用当前设置。已有笔记再次保存且源未变时仍为“内容未变化”，不会触发图片搬家。

上传的图片由浏览器持久队列持有；Obsidian 接收端暂存到内存，决定最终笔记路径后才写入附件位置。接收端在此期间重启时，浏览器按原请求重传。对于尚不存在且所在目录无其他笔记的新目标，使用短暂的自有上下文笔记调用官方附件 API，随后按 Obsidian 的删除偏好移除；异常退出可能遗留标明用途的上下文文件。不会覆盖目标笔记，也不删除现有附件。

0.1.3 修复引用转换导致整篇无法保存的问题。对照 Pionxzh `citations.ts` 和 OwlCt `processContentReferences` / `cleanMessageContent`，补回引用格式字符 U+E203/U+E204 的规范化。已识别引用沿用上游来源链接和来源列表转换；无法还原的引用/富标记以「引用未解析」或「ChatGPT 标记未解析」保留原始标记的 Unicode 转义文本，不猜测来源地址，不静默删除，也不再仅因标记残留拒绝全文。代码、公式和原文标点空白不做该改写。

用户 0.1.2 报告已确认 22 条记录、5 条面向用户消息校验通过；未包含残留标记的具体类型，因此不宣称已识别其确切格式。更新后的真实聊天保存和引用显示仍待验证。

0.1.2 修复已定位的 `UNSUPPORTED_CHANNEL`：面向用户的 assistant `commentary` 消息此前被误拒绝。参考 Pionxzh 的导出分类策略，现保留其正文及顺序；内部推理、隐藏消息、工具调用继续排除，未完成消息和未知通道继续拒绝。逐条保留原始消息 ID，因此显示的消息数包含 commentary，可能多于页面问答轮数。

0.1.1 已修复笼统错误提示、增加「复制诊断」并补齐附件字段兼容。用户随后提供的诊断证实本次失败由 commentary 通道触发，发生于提交前，没有保存笔记。该报告完整获取 22 条记录，已识别 4 条用户/助手消息、排除 17 条内部记录，剩余 1 条 commentary 此前被拒绝。对应合成回归现保留 5 条消息。真实聊天更新后的最终保存回执仍待用户确认。

若更新后仍失败，请点击「复制诊断」反馈。诊断不含正文、来源链接、文件名或令牌。复制受限时，右键扩展图标→「最近保存状态」，展开诊断详情手动复制。

## 安装

Obsidian Alpha 已安装并启用在本项目的专用 `p0-vault` 中，原 P0 插件和测试报告保留。Alpha 从 127.0.0.1:27125–27134 选择空闲端口，不占用已有监听；浏览器通过 Vault ID 定位，不把端口号当仓库身份。

1. Chrome 打开扩展管理页，选择「加载已解压的扩展程序」，加载 **`<项目目录>\dist\alpha\chrome-extension`**。新扩展名称是 **AI Inbox**；旧扩展名为 AI Inbox P0，请使用新扩展。
2. 保持目标 Obsidian 仓库打开并启用 AI Inbox。没有打开时，保存会直接失败。
3. 返回 ChatGPT 普通聊天，等待加载及回复结束，**直接点击工具栏 AI Inbox 图标**。首次配对时核对两边显示的 6 位码，在 Obsidian 点击「允许连接」。确认后继续保存。
4. 多仓库首次使用时选择目标。之后右键图标→「切换仓库 / 设置」可以随时选择另一个目标，选择后记为默认。

日常直接点击图标即可。无弹窗保存按钮、消息范围或保存模式选择。默认笔记位置为 `AI Inbox`；如需调整，在 Obsidian 设置中修改文件夹并点击「应用」，只影响新建笔记。重置连接会撤销旧凭据，需要再次确认配对。

## 这次如何判定成功

看到页面右下角「已保存 / 已更新 / 内容未变化 / 本地修改已保留，另存了新笔记」之一，且显示笔记路径、消息数和图片数，才表示收到 Obsidian 提交回执。可主动点击「在 Obsidian 中打开」。

请先用之前那条含上传图的聊天检查：全文和图片是否出现在一份 Markdown 中。再次点击应为「内容未变化」。在 Obsidian 正文末尾写一句自己的内容，再点击保存，应另存日期时间笔记，旧笔记中的修改仍在。

出错时不会显示保存成功。保持 Obsidian 打开后再次点击；如果上次结果未知，会先查询原请求，再继续，避免重复另存。反馈卡中的错误码可以直接反馈，不需要粘贴连接信息。

## 当前边界与数据

只支持 `https://chatgpt.com/c/...` 普通聊天及其当前分支，不支持临时聊天、分享页、账户批量导出。需页面实际发出受支持的当前会话请求；未观测到时提示刷新。

代码、公式、表格和普通 Markdown 保留；已识别引用转换为可点击来源，未知引用原始标记以明确「未解析」的字面文本保留。看到该标签意味着相应来源链接或富卡片未还原，并非已完整支持该组件。非图片附件保留名称与可取得的稳定文件 ID，不下载。图片 alt 存在时保留为本地 Markdown 图片的替代文字。未知 HTML、无法解析的图片格式/地址、图片与普通链接共用同一引用定义等情况明确失败，不能当成已支持的完整保存。

图片凭据只在 ChatGPT 页面的隔离上下文内短暂使用，不发送到 Obsidian；签名图片地址在扩展持久化前替换为摘要引用。正文和图片的待提交记录存 IndexedDB，收到回执后删除；连接凭据和最近结果存受信任扩展存储。插件 `data.json` 保存连接、当前目标、hash、恢复日志与幂等回执。当前回执索引保留，不自动删除历史回执或用户笔记；孤立图片不自动清理。

处理上限按代码执行：单张图片 25 MiB、总图片 250 MiB、图片 1000 张、消息 20000 条、提交 JSON 24 MiB、单文本块 2 MiB、最多 100 个分页。浏览器到隔离脚本以 64 KiB 分块传输图片，本机 HTTP 按整张图片提交，失败重传整图；采用整图哈希及幂等重传，减少首版中间状态，不提供跨 HTTP 请求的续传偏移。这些是拒绝边界，不是大容量验收承诺。

构建使用 Node.js 24：`npm ci`、`npm run check`。运行测试仓库安装脚本前检查专用 marker，脚本拒绝修改普通仓库。浏览器回归脚本 `scripts/verify-alpha-browser.mjs` 使用本机 Playwright 和独立测试配置，参数见脚本；不会连接用户现有浏览器。
