# AI Inbox 交互约定

日期：2026-09-12。来源：用户指定 UI 任务 `01a0934e-d229-7b42-9a5b-de2905d9e05a` 的最终修订，以及该任务的 `interaction-design.md`。已采用最后一次关于图标一致性的修订，早期“徽标显示上次结果”方案作废。

## 正式版本的入口

2026-09-12 最新确认：自动发现 + 首次确认配对；切换仓库即更新默认。Obsidian 未运行时直接失败，不离线暂存，不提供唤起应用按钮。0.2.0 的工具栏图标重绘为原创“对话气泡 + 收件托盘”；以下固定状态/一键保存约定继续有效。

- 左键点击工具栏 AI Inbox 图标立即保存当前完整聊天；移除 `default_popup`，用 `action.onClicked`。不先打开弹窗再点击保存。
- 图标、颜色、尺寸和保存 tooltip 始终保持一致。进行中、成功、失败、下一次操作都不叠加历史徽标或禁用样式。
- 进行中再次点击只恢复显示当前进度；不重复提交。结果未确认时恢复或查询原请求。
- 工具栏右键提供「切换仓库 / 设置」和最近保存状态。选择列表显示运行中仓库，首次连接需要在目标 Obsidian 确认一次，成功连接后立即作为默认。网页右键保存默认开启，仅支持的聊天页面显示；即使选中文字也保存全聊天，可在设置关闭。
- 快捷键默认未绑定，只声明 `_execute_action`，通过 Chrome 的快捷键设置配置。三种入口复用一个任务处理函数。

Chrome 官方说明 [action](https://developer.chrome.com/docs/extensions/reference/api/action)、[contextMenus](https://developer.chrome.com/docs/extensions/reference/api/contextMenus)、[commands](https://developer.chrome.com/docs/extensions/reference/api/commands) 作为实现依据。使用标准 API 和已有扩展结构，不另造快捷键录入器或系统通知服务。

## 状态反馈

页面右下角单张反馈卡，同一请求更新同一卡片，不抢焦点、改变滚动位置或自动打开 Obsidian。显示真实读取、图片、写入阶段，不虚构百分比。

普通成功/无变化默认显示 6 秒，另存提示 8 秒；悬停、焦点在卡内或页面不可见时暂停自动隐藏。失败、未完成和未知结果保留直到关闭或后续操作处理。关闭只隐藏，不取消任务，也不清除真实状态。

新任务开始立即替换旧结果。成功按钮由用户主动点击后才打开 Obsidian。无法显示网页反馈时，当前用户点击可以打开/复用扩展状态页；后台任务结束不抢焦点，结果留在最近状态中。图标仍保持不变。

状态按标签页、聊天身份和请求隔离；不能把聊天 A 的完成显示在聊天 B。只有收到服务端完整提交确认才显示保存成功。原请求结果未知时先查询，不能直接生成新请求导致重复另存。

## 设置、语言和可访问性

默认仓库摘要、运行中仓库选择列表、刷新、语言、网页右键开关及快捷键设置说明。首次连接自动交换凭据，不提供 JSON 输入框。目标文件夹在 Obsidian 配置，不增加日常保存模式或范围选择。

语言默认跟随浏览器：zh-* 为中文，其余回退英文；设置允许中文/English 覆盖并持久化。所有 UI 文案统一语言资源；不翻译聊天正文、笔记标题、仓库名或路径。

正常状态 `role=status`，需处理错误 `role=alert`；不只通过颜色表达结果。可键盘操作，焦点在卡内不自动关闭，支持英文换行与减少动画偏好。

## 在主工程中的执行顺序

P0 保留明确标识的测试入口，不把尚未实现的正式保存伪装成成功。这一轮测试 UI 先改为直接显示“消息抓取通过”“图片已写入并回读一致”等摘要，JSON 收到诊断详情，提供复制诊断。当前写入的是测试图片和预览，不是完整聊天笔记。

P1 建立独立语言资源和状态模型；P4 接入正式 toolbar action、单卡反馈、设置、右键和快捷键。依据现有 exporter、官方 Web Clipper 和 Chrome 官方样例检查实现，再填补 AI Inbox 自己的状态恢复与保存规则。独立网页原型中的模拟定时器、非空即连接成功、固定成功结果不得搬入真实扩展。

新增验收：多次操作图标一致；快速重复点击不重复提交；切换聊天状态隔离；英文窄屏；无障碍反馈；受限页面降级；右键开关默认开启；快捷键默认空；未知结果查询原请求。
