# 连接和仓库选择：已确认方案

2026-09-12，取代此前“离线收集 + 打开 Obsidian 并继续”讨论稿。用户明确不采用离线暂存和启动按钮。以下方案已在 0.2.0 实现。

## 连接与选择

1. 自动发现运行中且启用了 AI Inbox 的仓库。每个插件从本地 27125–27134 端口池选择空闲端口，避免多个 Vault 争用固定端口。
2. 首次只有一个 Vault：点击保存自动选中，浏览器与 Obsidian 显示同一个配对码，用户在 Obsidian 确认一次，后续继续保存。凭据自动交换，不要求复制粘贴。
3. 多个 Vault 且没有默认：打开仓库选择页，连接成功后成为默认。
4. 右键图标→「切换仓库 / 设置」，用户随时选择其他仓库；成功连接后它成为默认。已授权仓库不再弹配对确认。
5. 默认仓库未打开时直接失败，绝不因为另一个 Vault 可用而擅自改变目标。
6. 凭据保存在扩展受信上下文存储中。旧版连接按 Vault ID 沿用；重置连接后需要重新确认。

## 未运行与中断

- 开始抓取前确认目标连接。未运行/插件未启用：显示失败，不读取新聊天、不建立离线待发送记录。
- 没有“打开 Obsidian 并继续”按钮，没有启动时自动投递，没有后台轮询重试任务。
- 已经开始提交而丢失回执的情况，仍保存原请求恢复记录。用户手动重试时先核对回执，防止重复另存；这不是新增离线收集功能。

## 配对协议边界

发现接口只返回应用/协议标识、Vault ID 和名称。配对请求与轮询都校验来源和浏览器扩展身份，轮询需携带随机 256 位秘密。配对码用于两侧目视核对，不作为获取凭据的唯一证明。仅目标仓库明确确认后才能取得凭据；秘密只在浏览器后台内存保存，不进入聊天页或诊断。配对 120 秒过期，窗口关闭、拒绝或插件停用不会完成授权。数据写入路由仍需令牌及 Vault ID。

此版本最多发现端口池内可用的服务，并非枚举机器上所有 Obsidian 仓库。复制整个插件数据导致同一个 Vault ID 同时出现时拒绝选择，不随机发送。

## 图标

原创 SVG：`spikes/extension/icons/icon.svg`。圆角墨绿底、浅色对话气泡与收件托盘，提供抗锯齿 16/32/48/128 PNG。固定颜色、图形、tooltip，无状态徽标。开发时通过 `scripts/generate-icons.mjs` 生成 PNG；正常构建仅复制版本化图标文件，无新增产品依赖。
