# AI Inbox 验收用例

版本：1.1 · 更新：2026-09-12 · 状态：验收用例集；已执行证据及未完成项见 `alpha-testing.md`。

依据：`requirements-baseline.md`、`detailed-design.md`。本文定义发布门槛；单元测试、合成端到端与真实 ChatGPT 验收分别记录，不能把通过部分用例当成全表通过。

## 0. 0.2.0 连接与入口补充

| 编号 | 操作 | 必须满足 |
| --- | --- | --- |
| C20-01 | 首次只有一个运行中仓库，点击保存 | 两侧配对码一致，目标仓库确认前不发放令牌；确认后自动继续保存 |
| C20-02 | 多个仓库、未设默认 | 先选择，不提前抓取；成功连接后记为默认 |

| C20-05 | 所有接收端关闭 | 明确失败，不新增队列，不提供打开应用按钮 |

## 1. 测试方法与门槛

- 单元层：决策矩阵、hash 规范、Schema、命名、渲染、frontmatter 分割。
- 集成层：真实文件与受控 VaultStore、HTTP、资源分块、索引和恢复日志；文件系统替身用于精确故障注入。
- 真实端到端：Chrome 扩展 + ChatGPT 自建聊天 + Obsidian 测试 Vault，覆盖编辑器、权限、重启和离线图片显示。
- 不能只靠 mock 测试证明页面完整性或 Obsidian 编辑保护，二者必须有真实应用证据。
- 以下用例默认均为发布阻断项。特定不支持页面的通过条件是正确拒绝，而不是要求额外实现该平台。
- 典型性能目标如 L01 未达成，可先优化或明确修订目标；不得用性能原因豁免内容完整性与编辑保护。

每次执行记录实际系统/浏览器/Obsidian/适配器版本、样本编号、结果和证据路径。正文保护用例保留操作前后实际文本比较，图片用例比较字节摘要。

## 2. 抓取与渲染

| ID | 场景与步骤 | 预期结果 | 需求 |
| --- | --- | --- | --- |
| A01 | 打开含多轮问答的聊天，点击一次保存 | 所有消息按顺序保存，无消息选择或范围配置 | R01、R02、R07 |
| A02 | 至少 200 条消息，停在中部或底部后保存 | 第一条到最后一条完整；滚动位置不改变结果 | R01 |
| A03 | 历史未加载完整或虚拟列表只渲染一部分 | 能完成加载并验证，或明确失败；禁止截断成功 | R01 |
| A04 | 保存期间继续生成、切换聊天、编辑提问 | 本次不提交混合/半截快照；反馈可重试原因 | R01、R05 |
| A05 | 编辑早期问题或切换重新生成回答 | 保存当前选中分支全部消息，不混入互斥旧分支 | R01、R04 |
| A06 | 代码含反引号、缩进、空行、中文、HTML | 代码内容原样保留，围栏正确，无意外执行 | R02 |
| A07 | 表格、嵌套列表、引用、链接、段落硬换行 | 信息及结构可读，无误删空白、错位表格 | R02 |
| A08 | 行内与块级公式 | 保存对应数学源码并在 Obsidian 正确呈现 | R02 |
| A09 | 回复含评分按钮、头像、复制按钮、字面 wiki 语法 | 排除 UI 噪声；原文字面链接不变成本地文件嵌入 | R02 |
| A10 | 临时聊天、分享页、无稳定身份或未支持特殊内容 | 明确拒绝/提示不支持；不冒充普通聊天部分保存 | R01 |

## 3. 保存行为

| ID | 场景与步骤 | 预期结果 | 需求 |
| --- | --- | --- | --- |
| S01 | 首次保存 | 新建一份笔记，建立目标及 hash 基线 | R03 |
| S02 | 来源和本地均未变化，再点保存 | 不新建，不改正文/属性；正常资源无需重写 | R03、R04 |
| S03 | 来源增加消息，本地未改 | 原路径完整刷新，noteId 不变 | R04 |
| S04 | 来源修改历史消息或标题，本地未改 | 正文整体刷新，无重复拼接；文件名保持用户当前名称 | R04 |
| S05 | 本地修改正文，来源也有变化 | 旧笔记逐字不变，新建日期时间笔记 | R05、R10 |
| S06 | 本地修改正文，来源完全不变 | 仍然新建日期时间笔记；不可提前按 sourceHash 短路 | R12 |
| S07 | S05/S06 另存后，再次保存 | 只检查新目标；新目标未变且来源未变时不重复另存 | R03、R05 |
| S08 | 已退休的旧笔记被编辑或撤销，新目标未改 | 旧文件不影响下一次保存选择 | R05 |
| S09 | 只添加 tags/status/YAML 注释，来源更新 | 最新 YAML 原文完整保留，正文可刷新 | R11 |
| S10 | 改正文标题、一个空格、空行或代码缩进 | 判为正文编辑并另存；仅 CRLF/LF 转换不另存 | R05 |
| S11 | YAML 未闭合或身份字段被删除/改写 | 保守另存，不错误切割/覆盖文件 | R05、R11 |

## 4. 身份、路径与命名

| ID | 场景与步骤 | 预期结果 |
| --- | --- | --- |
| F01 | Obsidian 内重命名目标，正文未改 | 再次保存更新新路径，不重建原标题文件 |
| F02 | 在 Vault 内移动目标，正文未改 | 新位置刷新，不搬回 Inbox |
| F03 | 应用关闭时改名后重开 | 唯一 noteId 可重定位，基线仍可信；歧义则保守新建 |
| F04 | 删除当前目标后再主动保存 | 创建新的当前目标，不覆盖旧历史版本 |
| F05 | 删除/损坏插件索引但保留所有笔记 | 不能用当前笔记 hash 冒充未编辑基线，不覆盖现存笔记 |
| F06 | 复制笔记产生重复 noteId，并造成路径映射失效 | 不猜测覆盖对象，保守新建 |
| F07 | 同秒多次另存、有同名普通笔记 | 日期后序号避让；普通文件逐字不变 |
| F08 | 标题为保留名、含路径穿越/非法字符或超长 | 输出合法 Vault 内路径，不逃逸、不覆盖 |
| F09 | 修改 Inbox 目录后更新旧目标/另存新目标 | 更新留在旧目标当前位置；新建使用新 Inbox |

## 5. 图片

| ID | 场景与步骤 | 预期结果 |
| --- | --- | --- |
| I01 | 用户上传图 + 助手生成图 | 两者均下载为本地文件；断网且关闭 ChatGPT 后仍能显示 |
| I02 | 多轮多图及同图重复出现 | 对应位置、顺序、alt 正确；同字节资源可复用 |
| I03 | 同张图签名 URL 变化，实际字节相同 | 不因签名变化制造新的来源版本 |
| I04 | URL 相同但实际图片字节变化 | sourceHash 变化；按当前本地编辑状态更新/另存 |
| I05 | 某张图片 403、404、超时或过期且无法重新解析 | 不提交笔记、不推进目标；反馈具体失败并可重试 |
| I06 | 大图跨多个上传块，途中断开后继续 | 分块重放不重复资源；整图长度和 SHA-256 校验正确 |
| I07 | 图片被截断或返回 HTML 登录页，MIME 与字节不符 | 拒绝提交，不产生伪图片成功 |
| I08 | 新导入图片已存在且字节相同 | 验证后复用，不重复落盘 |
| I09 | 已存在摘要命名文件被用户改写 | 不覆盖；保护旧图，另存笔记/分配安全新资源路径 |
| I10 | 用户删除本地图片但正文未改，再保存相同来源 | 可恢复同摘要图片，笔记不无故新建 |
| I11 | 用户手动删/改正文图片引用，再保存 | 旧笔记不修补；另存新笔记并包含来源全部图片 |
| I12 | 外链图、blob 图、SVG、缩略图/原图 | 按验证的适配流程本地化；受限/危险/不支持时明确失败，不默默用截图或缩略图顶替 |

## 6. 并发与故障恢复

| ID | 场景与步骤 | 预期结果 |
| --- | --- | --- |
| C01 | 图片下载期间用户编辑正文 | 提交时重新检查，旧编辑不丢，另存新文件 |
| C02 | 编辑器缓冲未落盘、多个视图同时编辑 | 正文编辑触发另存；仅属性缓冲等待正常落盘后保留并更新；无法可靠区分时保守保护 |
| C03 | 重复点击或同 requestId 重发 | 一个逻辑提交；返回一致结果，不重复另存 |
| C04 | 两标签页保存同一聊天，旧请求图片上传较慢 | 服务器 revision/接收序号阻止晚到旧请求覆盖已提交结果 |
| C05 | 先完成一个任务，再主动保存另一条当前分支 | 作为新的主动保存处理；不凭消息数减少就误判过期 |
| C06 | 准备日志后用户只改 YAML/同时重命名 | 中止旧计划后重规划，保留最新属性和身份，不按旧全文覆盖 |
| X01 | 写任何 Vault 文件前暂存或日志保存失败 | 不改变目标和正文，显示失败 |
| X02 | 图片发布后、Markdown 前应用崩溃 | 旧笔记不变，恢复可继续；允许无害孤立图片，不误报成功 |
| X03 | Markdown 成功、索引失败后崩溃 | 根据 pending 新全文/noteId 补齐索引；不再创建同请求笔记 |
| X04 | 恢复前用户又编辑了目标文件 | 不自动回滚或覆盖；保留用户内容，恢复采取保守另存 |
| X05 | 关闭反馈、service worker 被终止后再次点击 | 恢复原任务/查询原请求，不凭内存丢失重复新建 |
| X06 | 提交成功但 HTTP 响应丢失 | 查询同 requestId 返回原结果 |
| X07 | 相同 requestId 发送不同 payloadHash | 409 冲突，不修改文件 |
| X08 | 索引/恢复日志损坏或算法版本无法迁移 | 保守保护现有文件，不静默认为可覆盖 |
| X09 | 磁盘满、拒绝写入、插件关闭、暂存/receipt 过期 | 状态可解释；不无限重试；清理后同 ID 由墓碑拒绝，不能悄悄作为新保存重放 |

## 7. 通信与界面

| ID | 场景与步骤 | 预期结果 |
| --- | --- | --- |
| N01 | 无令牌/错误令牌/重置后的旧令牌 | 请求拒绝，无 Vault 内容泄漏 |
| N02 | 目标端口被另一个 Vault 或程序占用 | 不写到错误目标；扩展检查协议和 Vault ID |
| N03 | 从网页伪造消息、来源请求任意本机 URL/路径 | 限制 sender、Schema、来源域与端点，不能成为通用代理 |
| N04 | 外部图片重定向至私网/localhost 或异常 scheme | 下载拒绝，不把图片 URL 变成本机探测入口 |
| N05 | 其他机器连接/向接收器请求读写任意笔记 | loopback 外不可用，未定义能力拒绝 |
| N06 | 超限 JSON、图片、块数或数量，非法块摘要 | 解析/提交前拒绝，已有文件不变 |
| N07 | 检查日志、导出包、content script 可读存储 | 无正文、Cookie、令牌、签名 URL 泄漏到非预期位置 |
| U01 | 清洁环境安装连接 | 一次连接后能一键保存，不要求模型 Key/独立 helper |
| U02 | 正常连续保存多次 | 一个主要按钮，无消息范围、模式、预览或确认步骤 |
| U03 | 未打开 Obsidian、未完成生成、图片失败 | 文案准确且可重试，不给出虚假的成功提示 |
| U04 | 关闭反馈又恢复、保存另一个聊天 | 状态与原任务相符；不会把 A 的结果显示成 B 的成功 |
| U05 | 禁用/卸载插件后查看导出文件 | Markdown 与本地图片仍可读；接收端口释放 |
| U06 | 初次、保存中、成功、失败后点击工具栏 | 图标与保存 tooltip 始终相同，不显示上次结果徽标；一次点击直接保存 |
| U07 | 自动语言、中文、English 与窄窗口 | UI 完整翻译和换行；聊天正文及路径不翻译 |
| U08 | 网页右键与快捷键 | 右键保存默认开、可关闭；快捷键默认空，在 Chrome 设置；与工具栏复用完整聊天保存 |
| U09 | 悬停、键盘聚焦反馈卡及受限页面 | 不抢焦点；焦点内不自动关闭；必要时状态页降级；不添加系统通知权限 |

## 8. hash 与容量

| ID | 场景与步骤 | 预期结果 |
| --- | --- | --- |
| H01 | 相同来源以不同对象键顺序/采集时间输入 | sourceHash 相同 |
| H02 | 正文空白、角色、消息顺序、图片字节改变 | sourceHash 按规范改变 |
| H03 | 图片 URL、请求 ID、adapterVersion 变化但内容相同 | sourceHash 不受这些元数据影响 |
| H04 | renderer/hash/normalization 版本升级 | 经迁移或保守另存，不误覆盖用户笔记 |
| L01 | 1 MiB、100 条消息，无图片，本机提交多次 | 记录 P95 和硬件环境，目标抓取后小于 2 秒 |
| L02 | 接近单图/总图/消息数上限 | 任务可完成，内存受控，界面不假死；记录实测峰值 |
| L03 | 超过任一上限 | 明确失败，无内容截断，无部分成功 |

## 9. 最小回归演示

发布前必须在真实应用连续完成以下链条：

1. 包含代码、公式和图片的完整聊天，一键保存，断网图片仍可见。
2. ChatGPT 增加消息，本地未改，原文件刷新。
3. 添加 tags，ChatGPT 再增加消息，tags 和 YAML 注释仍在。
4. 编辑正文，ChatGPT 不变，再次保存产生日期时间新文件，旧文完全不动。
5. 立即再次保存，不产生第三份文件。
6. 移动新文件后再续聊保存，更新移动后的文件。
7. 模拟响应丢失、重启插件和扩展，重试同请求不重复另存。
8. 检查输出笔记、图片、插件日志及错误提示与设计一致。


## 0.3.0 内容设置与语言

- C30-01：初次安装/从 0.2.0 升级，思考和正文标题默认关闭，连接与索引保留。
- C30-02：开启思考，摘要按源顺序保存到默认折叠引用块；展开后的 DOM 消息 ID 不导致分支误判。
- C30-03：关闭思考保留普通回答、普通过程消息、图片及原有章节标题；不根据正文关键词删除内容。
- C30-04：源未变化时切换标题或思考开关，下次保存按新设置更新；本地编辑后则另存。
- C30-05：捕获与提交之间设置变化，拒绝新写入并提示重试；已提交的同一请求仍返回原回执。
- C30-06：中英文原生控件、弹窗和错误提示可切换；跟随 Obsidian，其他语言回退英文；原文不翻译。
- C30-07：旧 Chrome 开启思考时要求升级；新 Chrome 对旧插件给出明确更新提示。
